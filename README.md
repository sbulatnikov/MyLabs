# MyLabs

Аддон для «Аллодов Онлайн»: личный лабиринт на всех персонажах аккаунта — рога изобилия, ресурсы лабиринта
и сундучок хранителя. Замена LabCalendar.

![Окно MyLabs](release/promo/MyLabs-1-cover.png)

Версия 0.9.1 (бета). Автор — NoMercy.

## Что умеет

- **Рога изобилия.** У каждого рога видно, что запущено, что назначено и сколько дней осталось. Когда вы заговорили
  с рогом, аддон сам забирает готовую добычу и запускает назначенное. Назначать можно любому персонажу, не заходя им в игру.
- **Все персонажи аккаунта.** Слева — список персонажей: сколько рогов готово или простаивает, через сколько дней
  будет готов ближайший. В карточке персонажа — шесть ресурсов лабиринта.
- **Сундучок хранителя.** Для каждого персонажа выбирается, что брать: золото, слезу дракона, коралл или гранит.
  Аддон открывает все сундучки в сумке сразу.
- **Новый рог.** Цена следующего рога, сколько коралла не хватает и сколько эмбриума уйдёт на обмен.

Полное описание — [release/description.html](release/description.html), список изменений —
[release/changes.md](release/changes.md).

## Установка

1. Скачайте `MyLabs.pak` со страницы [Releases](../../releases).
2. Положите файл в `<папка игры>\data\Mods\Addons\`. При обновлении новый файл заменяет прежний.
3. Выключите LabCalendar: оба аддона выбирают ответы в разговоре с рогом и будут мешать друг другу.

## С чего начать

1. Зайдите персонажем в личный аллод и заговорите с каждым рогом изобилия — в окне появятся строки.
   Аддон узнаёт о роге только из разговора с ним.
2. Поговорите с прорабом — появится цена следующего рога.
3. Повторите на остальных персонажах. Данные общие для всего аккаунта.

## Команды чата

| Команда | Что делает |
| --- | --- |
| `/mylabs` | открыть или закрыть окно |
| `/mylabs auto off` | выключить автоматику: аддон только записывает; `auto on` — включить обратно |
| `/mylabs reset` | забыть рога текущего персонажа (строки соберутся заново из разговоров) |

## Ограничения

- Игра не даёт аддонам ни номера рога, ни его координат. Строка таблицы — это место, а не конкретный рог:
  соседние рога с одинаковой добычей и сроком могут поменяться строками. На то, что будет запущено, это не влияет.
- Срок до готовности точен до суток. «Готов» до разговора с рогом — это расчёт.
- Курс обмена «1 эмбриум за 5 коралла» взят из LabCalendar, в игре не проверен.
- Рога и сундучок узнаются по названиям в русском клиенте.
- Окно 989 × 811 точек: рассчитано на экран от 1080 по высоте.
- Два окна игры одновременно не поддерживаются.

## Нашли ошибку

Заведите [issue](../../issues): версия аддона, сервер, что делали и что получилось. Ошибки аддона игра пишет
в `Personal\Logs\mods.txt` — приложите строки с `MyLabs`.

# Разработчикам

## Что где лежит

```
lua/       скрипты в UTF-8 (при сборке переводятся в Windows-1251, концы строк CRLF)
             LibDnD.lua  перетаскивание окна и кнопки (чужая библиотека, уже в Windows-1251)
             Util.lua    строки, время, обёртки над виджетами
             Core.lua    данные, рога, валюты, сундучок, автоматика — без интерфейса
             UI.lua      кнопка, окно, выпадающий список
             Main.lua    запуск, события, реакции, команды чата
gen/       генератор ресурсов
             build.py    виджеты, тексты, текстуры DXT5
             assemble.py папка аддона целиком + проверка ссылок и имён виджетов
             pak.py      папка аддона -> MyLabs.pak (ZIP с путями Mods/Addons/MyLabs/...)
             tree.py     дерево виджетов в таблицу Lua — для тестов
             render.py   грубый предпросмотр окна в PNG
tools/     strip_debug.py — вырезает отладку из скриптов при сборке
assets/    значки ресурсов, фракций, рога и сундучка, шрифт
test/      прогон скриптов на заглушках API игры
promo/     генератор промо-карточек (PNG 1600x900)
release/   описание, краткое описание, список изменений и карточки текущего выпуска
observer-0.1.5/  прежний аддон-наблюдатель (писал разговоры с рогами в mods.txt) — инструмент исследования, в выпуск не входит
```

## Сборка

Нужны Python 3 с `numpy` и `Pillow` и `rsvg-convert` (пакет `librsvg2-bin` в Debian и Ubuntu).

```
python3 gen/assemble.py out                  ->  out/MyLabs — папка аддона
python3 gen/pak.py out/MyLabs out/MyLabs.pak ->  файл для data\Mods\Addons
```

Версия задаётся в одном месте — `ML.VERSION` в `lua/Util.lua`. Имя аддона в игре («MyLabs v0.9.1») и `<version>`
в описании аддона генератор берёт оттуда.

Отладочная сборка — с переменной `ALLODS_DEBUG=1`: в ней остаются блоки `--@debug … --@end` и строки с `--@debug`
в конце (журнал в `mods.txt`, команда `/mylabs debug`). Обычная сборка их вырезает, оставляя пустые строки, —
номера строк в ошибках совпадают с исходниками. В выпуск отладка не попадает.

## Тесты

```
sh test/run.sh                    обычная сборка
ALLODS_DEBUG=1 sh test/run.sh     отладочная сборка
```

Скрипт собирает аддон и прогоняет его на заглушках API игры в Windows-1251, как в игре. Кроме сборки, нужны `iconv`
и `texlua` или `luajit` (свой интерпретатор — `LUA=<путь>`). Те же проверки запускаются в GitHub Actions на каждый
pull request.

## Правила кода

- `pcall` не используем. Ожидаемый сбой обрабатывается проверкой перед вызовом или событием игры; над проверкой —
  комментарий `-- Ожидаем: <что может не получиться> — <что делаем>`. `xpcall` — только если функция игры падает
  в обычной ситуации и иначе нельзя, с комментарием `-- Почему xpcall: …`.
- Всё неожиданное не прикрываем: оно падает в `mods.txt` со стеком, и это ошибка аддона.
- Логика (`Core.lua`) не трогает виджеты, интерфейс (`UI.lua`) не вызывает игровые действия напрямую.
- Виджет меняется, только если значение изменилось; никаких действий в каждом кадре.
- В `lua/` — только символы, которые есть в Windows-1251.

## Ветки и выпуски

`main` — только выпущенное. Доработка — в ветке `feature/<коротко>` или `fix/<коротко>` и через pull request.
Выпуск — слияние в `main` и тег `v<версия>`; к выпуску на GitHub прикладывается `MyLabs.pak`.

## Где что хранится

Общая секция настроек `MyLabsData` (одна на все персонажи аккаунта):

```
db.chars[ключ] = { name, shard, fac, res = { granite, coral, embrium, meteor, supplies, mercs }, resAt,
                   horns = { [строка] = { st = busy|free|done, prod, amount, per (дней), seen (когда видели),
                                          assign (что назначено | "none"), x, y, n (точка разговора) } },
                   hornCount, cost (цена следующего рога), costFor, chest (что брать из сундучка), menu, vol }
db.order — порядок персонажей, db.auto — автоматика включена
```

Секция `MyLabs` занята LibDnD (положение окна и кнопки) — свои данные туда не писать.

## Как рог попадает в свою строку

Игра не отдаёт ни постоянного номера рога, ни его позиции; id объекта меняется при каждом входе в зону.
Внутри посещения рог привязан к строке по id. При новом посещении строка подбирается один к одному: сначала
по состоянию (что добывает, сколько дней осталось), затем по близости точки, с которой персонаж разговаривал с рогом.
